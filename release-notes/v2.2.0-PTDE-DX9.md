# Dark Souls: Prepare to Die Edition, FPS Unlock v2.2.0

Unlocks the frame rate and fixes the physics, camera, timers and HUD that were written for exactly 30 FPS. Files: `xinput1_3.dll` and `PTDE-FPS-Unlock.ini` (plus `dxvk_d3d9.dll` for the experimental DXVK), next to `DARKSOULS.exe`. Current Steam build only (`SizeOfImage` `0x11C2000`). Works with DSfix; set `unlockFPS 0` in `DSfix.ini`.

## A milestone, and a new direction

Until now this mod made the game run correctly above 30 FPS. From 2.2.0 it also makes the game run faster: more than twice the frame rate in some of the most demanding scenes, much faster where effects fill the screen, and no more stutters, all with no change in visual quality.

| Ryzen 7 5800X3D, RTX 3090, 4K | Before | 2.2.0 |
|---|---|---|
| Darkroot Garden, busiest spot (full of effects) | 79 FPS | 157-171 FPS |
| Undead Burg bridge | 45-125 FPS | 155-168 FPS |
| Blighttown | 58-73 FPS | 96 FPS, 129 with DXVK |

## New in 2.2.0

**Less work on the game's draw thread.** In busy places the draw thread, not the GPU, set the frame rate, and most of its time went to the game's own overhead. Every speed-up has its own switch:

- No per-frame wait for the GPU on the eye-adaptation copy (`AsyncReadback`). The one difference you could see in principle: the eye adaptation (the slow brightening or darkening when you step into or out of light, about a second long) starts two frames later.
- Everything else gives exactly the same picture: repeated sampler state calls skipped (`FilterSamplerStates`), the effects library's leftover debug checks off (`FastEffects`), 28 math helpers replaced with faster ones that give bit-for-bit the same results (`FastRenderMath`), the game's read locks without kernel calls (`FastReadLocks`), and the surfaces the game made and threw away every frame reused (`ReuseSurfaces`).

**No more hitch every 5 seconds** (`SteamPauseGuard`). On Windows the Steam client checks Wi-Fi about every 5 s, on the thread that answers games, and every Steam call made meanwhile waits (15 ms on a PC with Wi-Fi, with Steam online or offline). The game makes several every frame. Now its every-frame calls go only right after Steam has answered quickly (on a PC where Steam pauses), the lobby filter it set every frame waits for the next lobby search, and its online packets are sent from a thread of their own. On a PC without the pause, and on the Steam Deck, nothing is held back.

**No more slowdown while standing still** with fewer than four controllers: empty controller slots are checked once a second instead of every frame.

**DXVK** (experimental, off by default):

- **G-SYNC / FreeSync works** while Windows HDR is off (`DxvkExclusiveFullscreen = auto`). It needs exclusive fullscreen, and with HDR on Windows would switch HDR off for as long as the game holds it, so then DXVK keeps HDR and runs without variable refresh (Direct3D 9 has both). `true` takes exclusive fullscreen anyway.
- **Colors with Windows HDR:** NVIDIA's RTX HDR, if it is on for the game in the NVIDIA app, applies only under DXVK and crushes the shadows. Turn it off for the game for the same picture as Direct3D 9; the log says when it is active.
- On the Steam Deck and Linux, `DXVK = true` steps aside: Proton already runs the game on its own DXVK.

**A clearer INI.** The settings you may want to change come first: the frame rate cap, the refresh rate, borderless, the 16:10 fill, the intro, DXVK. The fixes and speed-ups follow below a line, on, as the mod is meant to be played. Your old INI keeps working: every setting is read wherever it stands, and a new one is on when it is missing.

## Install

Copy the files next to the game exe (`dxvk_d3d9.dll` only if you want to try DXVK). Upgrading: replace `xinput1_3.dll` (and `PTDE-FPS-Unlock.ini` for the new layout, or keep yours: it works as it is). Recommended: exclusive fullscreen with `FullscreenRefreshRate = 0`. Back up your saves. Well tested with DSfix; official online play is untested.

**Online play: no guarantees.** The mod modifies the game in memory; using it on official servers could risk a ban. Use at your own risk; no responsibility is accepted for bans or lost progress (see the README and LICENSE).

## Known limits

Riding the edge of a short step can leave you stuck against it at a high frame rate. In-engine cutscene cameras are blended; a hard cut still snaps, and pre-rendered movies stay 30 FPS. Send `PTDE-FPS-Unlock.log` and any `*-crash.dmp` with bug reports.
